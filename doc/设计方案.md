## ODMatrix Viewer 原生架构设计文档

### 1. 核心技术栈说明

* **构建工具**：Vite（仅用于本地开发服务器、ESM 模块打包和生产环境构建，不在客户端引入任何运行时）。
* **UI 与交互**：Vanilla JavaScript (ES2022+) + DOM API。
* **样式方案**：原生 CSS3 + CSS Variables（自定义属性）+ Flexbox/Grid 布局。
* **状态管理**：基于 `Proxy` API 实现的轻量级原生响应式状态机。
* **数据流转**：`ReadableStream` + Web Worker + `ArrayBuffer`（零拷贝转移）。
* **渲染引擎**：HTML5 `<canvas>` 2D API。

### 2. 目录结构设计

摒弃组件化框架后，我们需要通过良好的文件组织来防止代码变成“意大利面条”。采用**按功能职责划分**的模块化设计：

```text
odmatrix-viewer/
├── index.html               # 唯一入口 HTML，包含所有静态 DOM 骨架
├── style.css                # 全局样式与 CSS 变量定义
├── vite.config.js           # Vite 极简配置
└── src/
    ├── main.js              # 应用入口，负责初始化和模块组装
    ├── state.js             # 基于 Proxy 的全局状态机
    ├── core/                # 核心逻辑
    │   ├── parser.worker.js # CSV 流式解析与网格聚合 (Web Worker)
    │   └── matrix-math.js   # 坐标转换与仿射变换矩阵运算
    ├── ui/                  # DOM 操作与交互绑定
    │   ├── sidebar.js       # 左侧面板交互逻辑
    │   └── viewport.js      # 画布尺寸与底图滤镜控制
    └── render/              # 渲染引擎
        └── heatmap.js       # Canvas 绘制逻辑 (批量绘制、视口剔除)

```

### 3. 核心模块设计

#### 3.1 极简响应式状态机 (State Management)

没有了 Vue 的 `reactive`，我们使用 ES6 的 `Proxy` 来拦截对象赋值操作，实现一个极简的发布-订阅（Pub/Sub）模式。当状态改变时，自动触发注册的 UI 更新函数或重新渲染画布。

* **设计思路**：维护一个全局 `state` 对象。提供一个 `subscribe(key, callback)` 方法。当 `state[key]` 被重新赋值时，遍历并执行对应 `key` 的所有 `callback`。
* **存储内容**：当前交互模式、时间切片刻度（0-23）、激活的过滤器状态、解析完成的底图 URL 和聚合数据引用。

#### 3.2 UI 绑定与事件委托 (DOM Interaction)

在 Vanilla JS 中，频繁查询 DOM 节点会影响性能。

* **骨架预渲染**：所有静态的侧边栏、按钮、滑块直接写在 `index.html` 中，避免用 JS 动态生成 DOM。
* **DOM 缓存**：在 `ui/*.js` 模块初始化时，一次性使用 `document.getElementById` 缓存所有需要的 DOM 节点。
* **事件委托 (Event Delegation)**：对于面板上的多个复选框，不在每个元素上绑定事件，而是将 `change` 或 `click` 事件绑定在父级容器上，通过 `event.target.matches` 识别目标，减少内存占用。

#### 3.3 样式架构 (CSS Architecture)

不使用 Tailwind，依靠原生 CSS 实现暗黑控制台风格。

* **CSS 变量驱动**：在 `:root` 中定义所有的颜色基准。利用变量实现状态切换（例如按钮的激活/置灰）。
* **命名空间**：采用 BEM（Block Element Modifier）命名规范，例如 `.sidebar__section`, `.btn--active`，防止样式冲突。
* **硬件加速**：针对底图的去色处理，强制开启 GPU 加速：
```css
.csl-map {
  filter: grayscale(100%) brightness(35%);
  transform: translateZ(0); /* 触发 GPU 合成层 */
}

```



#### 3.4 纯原生数据管线 (Zero-Dependency Parser)

为了达到真正的零外部依赖，甚至可以**不使用 Papa Parse**。针对我们固定的 CSL CSV 格式，原生 API 足以应对。

* **Stream API**：使用 `file.stream().pipeThrough(new TextDecoderStream())` 获取文本块。
* **自定义 Chunk 分割**：在 Worker 中手动处理文本流，通过寻找换行符 `\n` 将字符串分割成行。
* **原生数据提取**：使用简单的 `String.prototype.split(',')` 获取坐标和类型字段，直接转换为离散网格坐标并塞入 `Map` 或 `TypedArray` 累加器。
* **转移至主线程**：解析完毕后，将扁平化后的 `Uint16Array` 等二进制对象转移（Transfer）给主线程。

#### 3.5 渲染引擎设计 (Canvas Rendering)

Canvas 负责最核心的热力块绘制。

* **主循环**：抛弃 React/Vue 的状态驱动思维，采用游戏开发中的理念。提供一个 `render()` 函数，当 `state` 发生变化（如拖动时间滑块、拖拽地图）时，触发一次 `requestAnimationFrame(render)`。
* **视图矩阵**：在 `state` 中维护相机的 `x`, `y` 和 `zoom` 属性。在 `render()` 中，使用 `ctx.setTransform()` 应用矩阵，然后只遍历在当前屏幕视口内的网格坐标，调用 `ctx.fillRect()` 绘制，实现千万级数据的丝滑浏览。
